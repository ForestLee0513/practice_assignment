# 행별 특성 두 개만 추가 및 동일 Logistic·5-fold 비교에 대한 결과

해당 코드를 실행 했을 때 결과값은 아래와 같이 출력된다.

      model  CV_F1  CV_std  valid_F1
   Logistic 0.5219  0.2092    0.3333
Logistic_FE 0.5324  0.1818    0.1818
CV는 선택용, valid는 진단용입니다. test는 아직 보지 않습니다.

CV와 valid의 차이

| 구분 | CV | valid |
|---|---|---|
| 사용하는 데이터 | train을 5개로 나눈 데이터 | 처음부터 따로 보관한 검증 데이터 |
| 평가 방식 | 4개 묶음으로 학습하고 1개로 평가, 총 5회 | train 전체로 학습한 모델을 valid에서 평가 |
| 목적 | 비교할 모델·특성 선택 | 선택한 방식이 별도 데이터에서도 작동하는지 진단 |

이 실습에서는 CV 결과로 선택하고, valid는 진단에 사용합니다. valid 점수를 보고 계속 특성을 수정하면 valid에도 간접적으로 맞추게 될 수 있습니다.

출력 변수의 의미

| 변수 | 의미 |
|---|---|
| Logistic | 기존 특성 4개로 학습하는 로지스틱 회귀 |
| Logistic_FE | 기존 특성에 파생 특성 2개를 추가한 모델 |
| CV_F1 | 5개 fold의 검증 F1 평균. 클수록 좋음 |
| CV_std | 5개 F1의 표준편차. 작을수록 fold 사이 점수 변동이 적음 |
| valid_F1 | train 전체로 학습한 모델을 별도 valid에서 평가한 F1 |

출력에서는 파생 특성을 추가했을 때:

- CV 평균은 0.5219 → 0.5324로 약간 높아졌습니다.
- CV 표준편차는 0.2092 → 0.1818로 줄었습니다.
- valid F1은 0.3333 → 0.1818로 낮아졌습니다.

따라서 CV 기준으로는 파생 특성 모델이 조금 우세하지만, 별도 valid에서는 성능이 떨어졌습니다. CV 개선 폭이 작고 fold별 변동도 있으므로, 특성 추가가 확실한 개선이라고 단정하기는 어렵습니다. 이 결과만으로 과적합이 확정되는 것도 아닙니다.

입력 변수와 파생 특성

| 변수 | 의미 및 현재 계산식 |
|---|---|
| input_chars | 입력 문자 수 |
| allowed_tools | 허용 도구 수 |
| task_type | 작업 유형 |
| priority | 우선순위 |
| failed | 예측할 실패 여부인 정답 |
| log_input_chars | log(1 + input_chars) |
| chars_per_slot | 현재 코드에서는 log_input_chars / (1 + allowed_tools) |

log1p는 큰 문자 수의 차이를 압축합니다. 분모의 1 + allowed_tools는 도구 수가 0일 때도 나눗셈이 가능하게 합니다.

다만 현재 chars_per_slot은 원래 문자 수가 아닌 로그 변환한 문자 수를 나눕니다. 이름만 보면 원래 문자 수를 나눈 것처럼 보일 수 있으므로, 나중에 의도한 계산식과 일치하는지 확인할 부분입니다.

NaN 처리 규칙

1. 파생 특성을 만들 때는 NaN을 그대로 둡니다.
   input_chars가 NaN이면 두 파생 특성도 NaN이 됩니다. allowed_tools만 NaN이면 chars_per_slot이 NaN이 됩니다.
2. 수치형은 해당 열의 중앙값으로 채웁니다.
   원래 수치 열과 파생 수치 열 각각의 중앙값을 사용한 뒤 StandardScaler로 표준화합니다. 파생 특성의 NaN도 해당 파생 열의 중앙값으로 채우며, 원본을 채운 뒤 다시 계산하지는 않습니다.
3. 범주형은 해당 열의 최빈값으로 채웁니다.
   이후 원핫 인코딩합니다. 학습 때 없었던 범주는 handle_unknown="ignore"에 따라 해당 범주의 인코딩 값이 모두 0이 됩니다. 이는 NaN 처리와는 별도 규칙입니다.
4. 중앙값·최빈값·표준화 기준은 학습 부분에서만 구합니다.
   CV에서는 각 fold의 학습 부분에서 구해 검증 부분에 적용합니다. 최종 valid 평가에서는 train 전체에서 구한 기준을 valid에 적용합니다. valid 데이터로 기준을 다시 계산하지 않습니다.

keep_empty_features=True는 학습 부분에서 전부 NaN인 열도 제거하지 않고 유지하는 설정이며, 현재 사용한 대체 전략에서는 그 열을 0으로 채웁니다.
