# LLM 답변 검증 결과

교육용 사례의 분류 결과

## 플랫폼 연결

### 분류 기준

```
format: JSON/응답에 필수 필드가 존재하는지 보는 구조 검증
evidence: 인용·출처 정보가 있는지와 적절한 근거인지 구분
factual_mismatch: 주장과 승인된 정답/원본이 모순되는지 사람·검증 규칙으로 확인
```

### 입력 내용

```python
CASES = [
    {"id":"F01","question":"파일을 어디에 보관하나요?",
     "source":"실습 파일은 개인 폴더에 보관합니다.",
     "answer":"실습 파일은 공용 서버 폴더에 보관합니다.","sources":["K01"]},
    {"id":"F02","question":"서버는 어디에서 실행하나요?",
     "source":"프로젝트 폴더에서 서버를 실행합니다.",
     "answer":"프로젝트 폴더에서 서버를 실행합니다."},
    {"id":"F03","question":"질문할 때 무엇을 함께 적나요?",
     "source":"오류 메시지와 시도한 작업을 함께 적습니다.",
     "answer":"오류 메시지와 시도한 작업을 함께 적습니다.","sources":[]},
]
```

### 검증 결과

#### F01

```json
{
  "id": "F01",
  "question": "파일을 어디에 보관하나요?",
  "source": "실습 파일은 개인 폴더에 보관합니다.",
  "answer": "실습 파일은 공용 서버 폴더에 보관합니다.",
  "sources": ["K01"]
}
```

분류 결과: 주장과 승인된 정답/원본이 모순  
분류 원인: 원본 RAG에서는 "개인 폴더에 보관"이라고 명시를 했으나, 실제 LLM 답변에서는 "공용 서버 폴더에 보관"으로 명시되어 있음.  
해결 방안: LLM과 원본 RAG응답의 토큰을 비교하며 "개인 폴더"와 "공용 서버 폴더"의 차이를 확인하고, 토큰을 조정하는 방향으로 할루시에이션 방지하는 것을 목표로 지정

#### F02

```json
{
  "id": "F02",
  "question": "서버는 어디에서 실행하나요?",
  "source": "프로젝트 폴더에서 서버를 실행합니다.",
  "answer": "프로젝트 폴더에서 서버를 실행합니다."
}
```

분류 결과: JSON/응답에 필수 필드가 존재하는지 보는 구조 검증  
분류 원인: 원본 RAG의 sources 필드가 존재하지 않음.  
해결 방안: FastAPI 내부에서 응답을 받고 JSON으로 응답을 반환할 때 sources 필드가 존재하는지 검증 필요 가급적 클래스로 직접 지정해서 반환하는 것을 목표로 할 것.

#### F03

```json
{
  "id": "F03",
  "question": "질문할 때 무엇을 함께 적나요?",
  "source": "오류 메시지와 시도한 작업을 함께 적습니다.",
  "answer": "오류 메시지와 시도한 작업을 함께 적습니다.",
  "sources": []
}
```

분류 결과: 인용·출처 정보가 빈 배열로 존재하여 적절한 근거인지 확인 불가  
분류 원인: LLM 답변에서 임의로 답변을 생성해 존재하지 않는 근거임에도 답변을 생성함.  
해결 방안: 실제 RAG의 근거가 존재하지 않는지 확인, RAG의 근거가 존재하지 않는다면 LLM에서 답변을 생성하지 않도록 예외 처리, RAG의 근거가 존재함에도 참조하지 않았다면 LLM의 프롬프트 수정을 권장함
