## 1. 준비와 실행

ZIP을 새 폴더에 압축 해제합니다. 이전 버전에 덮어쓰지 않습니다. 전날 사용한 Python 가상환경을 선택하고 VS Code에서 해당 **난이도 폴더를 폴더 열기**로 엽니다.

기존 환경에 XGBoost가 없다면 강사와 함께 먼저 설치합니다. 정확한 재현 환경이 필요할 때, 이 README와 requirements.txt가 있는 역할 폴더에서 아래를 실행합니다.

```powershell
python --version
python -m pip install -r requirements.txt
```

가상환경을 새로 만들 경우 역할 폴더에서 `python -m venv .venv`를 실행합니다. Windows PowerShell 활성화가 막히면 실행 정책을 변경하지 말고 `.venv\Scripts\python.exe -m pip install -r requirements.txt`로 설치한 뒤, VS Code의 `Python: Select Interpreter`에서 그 실행기를 선택합니다. macOS/Linux는 `.venv/bin/python -m pip install -r requirements.txt`입니다.

**검증 조합: Python 3.13.5 / numpy 2.3.5 / pandas 2.2.3 / scikit-learn 1.8.0 / xgboost 3.1.3 / scipy 1.17.0 / joblib 1.5.3 / threadpoolctl 3.6.0.** 최신 버전이라는 뜻이 아니라 이번 출력과 대조한 버전입니다. CPU로 실행하며 GPU·CUDA·인터넷 데이터 다운로드는 필요 없습니다. 패키지 설치에는 인터넷이 필요할 수 있습니다. 이미 같은 버전을 사용한다면 재설치하지 않습니다.

실습01~04는 XGBoost를 쓰지 않습니다. 05 이후 설치 오류가 있으면 오류 화면을 강사에게 보여 주고, 모델을 다른 모델로 몰래 바꿔 결과를 맞추지 않습니다. Windows·macOS에서는 직접 검증하지 않았습니다.

## 2. 전날과 동일한 데이터

기본필수의 `requests.csv`는 **10월26일 수정판의 정상20건 파일과 바이트 단위로 동일**합니다. `request_id`, `input_chars`, `task_type`, `failed`, `elapsed_ms`가 있습니다. 오늘 분류 입력에는 실행 후 알게 되는 `elapsed_ms`와 정답 `failed`를 넣지 않습니다. 결측·중복·손상 값이 없는 교육용 합성 자료입니다.

응용·심화는 기존 PPT의 100건과 전날 수정판의 `split_manifest.csv`를 그대로 사용합니다. manifest의 `position`까지 읽어 각 분할의 내부 순서를 지킵니다. 수치·범주에 있는 교육용 결측은 제공된 전처리에서 train 안에서만 대체합니다. 잘못된 파일·입력 예외를 구현하는 과제는 없습니다.

## 3. PPT와 달라지는 기본필수

| 항목 | 새 기본필수 | 응용·심화 |
|---|---|---|
| 공통 데이터 | 정상20건 | PPT의100건 |
| 바깥 분할 | train12·valid4·test4 | train60·valid20·test20 |
| 개별 실습02·03·05·06 | 글자 수1열 | 원래 입력4열 |
| 중요도 실습04 | 작은 숫자2열 원리 예제 | 변환8열 MDI / 심화는 원본4열 순열 추가 |
| 통합 입력 | 글자 수·작업 종류2열 → 3열 | 원래 입력4열 → 8열 |
| 교차검증 | train 안의3-fold: 학습8·평가4 | train 안의5-fold: 학습48·평가12 |
| Forest | 20개·깊이3 | PPT의100개·깊이4·최소 잎2 |
| 종합 프로젝트 | 분류 Tree·Forest 2후보 | 응용 분류4후보 / 심화 분류6·회귀6후보 |

기본필수 train에는 실패1이4건이므로 5-fold를 무리하게 적용하지 않습니다. 기본필수의 작은 표에서 얻은 수치를 기존 PPT의100건 수치와 비교하지 않습니다. 원리 예제01·04는 별도 작은 자료이며 성능 평가용이 아닙니다.

## 4. 지켜야 할 원칙

- **test는 보관합니다.** 데이터 분할·ID 관리 외에 모델 학습·변환·예측·평가·후보 선택에 넣지 않습니다.
- CV는 train 안에서 수행합니다. 결측 대체·원핫 인코딩을 먼저 전체 자료에 학습하지 않고, Pipeline 전체를 CV에 전달합니다.
- F1은 실패1의 발견을 보는 지표입니다. F1=0도 올바른 코드의 결과일 수 있습니다. 점수를 맞추려고 valid 행이나 정답을 바꾸지 않습니다.
- 예외 없이 끝난 것만으로 완료가 아닙니다. **TODO의 실제 설정, 예상값, 실제값, 설명**을 함께 확인합니다. `None`·`pass`·임시 설정은 미완성 표시입니다.

01~06은 독립 실행됩니다. 앞 파일을 못 끝내도 다음 실습을 시작할 수 있습니다. 07과08은 같은 프로젝트를 이어갑니다. 결과 숫자를 직접 적어 출력하거나 `expected/`를 입력으로 읽어 제출하지 않습니다.

## 5. 결과물과 폴더의 뜻

`data/`는 원본, `expected/`는 비교용 예상 결과, `outputs/`는 실행으로 만든 결과, `reports/`는 자신의 근거·한계를 적는 문서입니다. 기본필수는 폴더를 늘리지 않고 07번 실행 시 파일 옆에 결과 CSV를 만듭니다. 응용·심화의 outputs/는 배포 시 비워 둡니다.

강사용은 완성 코드·설명 주석·운영안·제작 검수 도구, 수강생용은 TODO 코드입니다. 수강생에게 자동 테스트 작성이나 복잡한 입력 검증을 요구하지 않습니다. **README만 읽고 실습을 진행할 수 있습니다.**

심화 모델은 직접 실행해 생성합니다. 외부에서 받은 출처 불명의 joblib/pickle을 읽지 않습니다. 자체 생성 모델도 동일 환경에서만 복원 결과를 확인하며, 다른 패키지 버전 호환을 보장하지 않습니다.
