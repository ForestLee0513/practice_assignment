# 앙상블 실험 보고서

이름: 이우림 / 실행일: 2026-10-27

## 1. 문제·데이터
요청 실행 전에 알 수 있는 입력 글자 수, 허용 도구 수, 작업 종류, 우선순위의 네 가지 정보로 실패 여부와 실행시간을 예측했다. 분류에서는 실패를 1로 두었고, 회귀에서는 실행시간인 `elapsed_ms`를 ms 단위로 예측했다. 데이터는 train 60건, valid 20건, test 20건으로 나누었다.

## 2. 선택 규칙
별도 탐색에서는 RandomForest의 잎 최소 표본 수를 2와 4로 정하고, 다른 조건은 고정했다. 동일한 5-fold 교차검증으로 비교한 뒤 분류는 CV 평균 F1이 높은 값, 회귀는 CV 평균 RMSE가 낮은 값을 선택했다. 동점이면 먼저 기록한 2를 선택하도록 했다. valid 점수는 결과를 확인하는 데 사용하고, 이를 보고 선택을 바꾸지는 않았다.

## 3. 숫자로 뒷받침한 근거 3개
1. 비교한 파일·모델·행과 숫자

별도 탐색 실험으로 RandomForest의 다른 조건을 고정하고, 잎 최소 표본 수인 `min_samples_leaf`를 2와 4로 바꾸어 비교했다. 각 후보를 동일한 5-fold 교차검증으로 평가했으며, 결과는 `outputs/exploration/summary.csv`를 기준으로 정리했다. 이 실험은 기본 프로젝트의 전체 모델 비교와 구분한다.

| 문제 | 잎 최소 표본 수 | CV 평균 | valid 점수 |
| --- | --- | --- | --- |
| 분류 F1 | 2 | 0.2800 | 0.2222 |
| 분류 F1 | 4 | 0.0000 | 0.2500 |
| 회귀 RMSE(ms) | 2 | 624.011 | 690.368 |
| 회귀 RMSE(ms) | 4 | 619.075 | 682.425 |

2. CV와 valid가 다른 점

분류에서는 잎 최소 표본 수가 2일 때 CV 평균 F1이 0.2800으로, 4일 때의 0.0000보다 높았다. 반면 valid F1은 4일 때 0.2500으로, 2일 때의 0.2222보다 높아 CV와 valid의 순위가 달랐다.

회귀에서는 잎 최소 표본 수가 4일 때 CV 평균 RMSE가 619.075ms로, 2일 때의 624.011ms보다 낮았다. valid RMSE도 4일 때 682.425ms로, 2일 때의 690.368ms보다 낮았다. F1은 높을수록, RMSE는 낮을수록 좋은 결과로 해석했다.

CV 평균은 train을 다섯 묶음으로 나누어 학습·평가를 반복한 점수의 평균이다. valid 점수는 train 전체로 학습한 모델을 별도로 남겨 둔 valid 데이터에 적용한 결과다. 학습·평가에 사용한 데이터 구성이 다르므로 두 결과의 순위가 달라질 수 있으며, 잎 최소 표본 수를 늘린다고 valid 성능이 반드시 좋아지는 것은 아니다.

미리 정한 CV 기준에 따라 별도 Forest 탐색에서는 분류의 잎 최소 표본 수를 2, 회귀는 4로 선택했다. valid 결과는 진단에만 사용하고 후보 선택에는 반영하지 않았다.

3. 회귀 또는 오탐·놓침 근거

회귀에서 잎 최소 표본 수를 2에서 4로 바꾸었을 때 CV 평균 RMSE는 약 4.936ms, valid RMSE는 약 7.943ms 감소했다. 두 결과 모두 오차가 줄었으므로, 비교한 두 후보 중에서는 잎 최소 표본 수 4를 선택했다. 다만 이 결과만으로 다른 데이터에서도 4가 항상 더 좋다고 판단하지는 않았다.


## 4. 오류 사례
오류 사례는 별도 Forest 탐색과 구분하여, 기본 실험의 `outputs/validation_predictions.csv`에 기록된 선택 모델에서 확인했다. 기본 선택 모델은 분류 Tree, 회귀 KNN15다.

| 구분 | 모델 | 요청 ID | 실제값 | 예측값 |
| --- | --- | --- | --- | --- |
| FP | Tree | R073 | 정상 0 | 실패 1 |
| FN | Tree | R044 | 실패 1 | 정상 0 |
| 회귀 오차 | KNN15 | R034 | 2608.000ms | 1327.267ms |

R073은 정상 요청을 실패로 판단한 오탐이고, R044는 실제 실패를 정상으로 판단해 놓친 사례다. R034의 잔차는 실제값−예측값으로 계산하면 +1280.733ms이므로, 실제보다 실행시간을 작게 예측했다.

## 5. 중요도와 한계
중요도는 기본 실험의 Forest를 대상으로 계산한 `outputs/feature_importance.csv`에서 확인했다. MDI는 학습 데이터와 변환 후 8개 열을 기준으로 하며, `input_chars`의 중요도가 0.564256으로 가장 높았다. 순열 중요도는 valid에서 원본 4개 열을 각각 섞었을 때 F1이 얼마나 감소하는지 확인한 값으로, `task_type`의 평균 감소량이 0.173651로 가장 컸다.

두 값은 사용한 데이터와 계산 방식, 열의 개수가 달라 직접 비교하기 어렵다. 중요도가 높다고 실패의 원인이라고 단정할 수 없으며, 작은 데이터에서 계산한 결과라는 한계도 있다. 이 결과는 별도 탐색에서 잎 최소 표본 수를 바꾼 모델의 중요도는 아니다.

## 6. 재현
기본 실험은 `outputs`에 저장된 비교표와 예측값을 확인했으며, 이번 보고서 작성 중 `main.py` 재실행 결과가 같은지는 확인하지 않았다. 별도 실험은 `python explore.py`로 실행하며, 조건과 결과는 `outputs/exploration/experiment.log`와 `summary.csv`에 기록된다.

`python -m unittest -v test_preprocessing.py`로 새 범주 처리와 필수열 누락을 검사했고, 두 테스트의 세부 사례 6개가 모두 통과했다. `restore.py`는 아직 복원 TODO가 남아 있어 ID·예측·확률 일치를 확인하지 못했다. 짝 실행도 아직 확인하지 않았다.

## 7. test 보관과 다음 수업
test 20건은 학습, 전처리 통계 계산, 교차검증, 후보 선택과 평가에 사용하지 않았다. 이번 자료는 작은 합성 데이터이고 valid도 20건이어서, 일부 예측만 달라져도 점수가 바뀔 수 있다. 같은 valid를 반복해서 확인한 점도 결과를 해석할 때 고려해야 한다.

최종 평가 전에는 입력 특성, 전처리 방법, 모델 설정, 선택 지표와 동점 규칙을 고정해야 한다. 별도 Forest 탐색에서는 분류의 잎 최소 표본 수 2, 회귀는 4를 선택했지만, 기본 프로젝트의 선택 모델인 Tree와 KNN15를 변경한 것은 아니다.
