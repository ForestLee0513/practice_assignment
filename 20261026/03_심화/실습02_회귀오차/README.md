## 추가 실험 · 지표별 선택과 이상치 제거

> 실험 환경: Python 3.13, scikit-learn 1.8.0, pandas 3.1.0, NumPy 2.5.4. 별도 표기가 없는 추가 실험 수치는 이번에 실행해 확인한 값이며 표시 자릿수로 반올림했다. 실험은 별도 메모리 복사본으로 수행했고 원본 CSV와 main.py는 변경하지 않았다.

### MAE와 RMSE가 다른 모델을 선택하는 사례

다음은 지표의 차이를 보이기 위한 가상 예측이며 실제 요청 데이터의 모델 출력이 아니다. 실제값을 모두 `100ms`로 두고 두 후보를 비교했다.

| 후보 | 실제값 | 예측값 | 절대오차(ms) | MAE(ms) | RMSE(ms) |
|---|---|---|---|---:|---:|
| A | [100,100,100,100] | [100,100,100,120] | [0,0,0,20] | 5.000 | 10.000 |
| B | [100,100,100,100] | [106,106,106,106] | [6,6,6,6] | 6.000 | 6.000 |

MAE는 A를, RMSE는 B를 선택한다. MAE는 오차 크기를 선형으로 더하지만 RMSE는 큰 오차를 제곱해 더 강하게 반영하기 때문이다.

업무 비용도 먼저 정의해야 한다. 예를 들어 오차 `1ms`마다 비용 1점을 부과하면 A의 총비용은 20점, B는 24점이므로 A가 유리하다. 반대로 `15ms`를 넘는 예측 오차가 발생할 때마다 SLA 대응 비용 100점을 추가하면 A는 120점, B는 24점이므로 B가 유리하다. RMSE는 큰 오차를 강조하는 지표이고, 실제 업무 비용은 이처럼 별도 식으로 계산해 확인해야 한다.

### 이상치 제거 규칙과 데이터 분리

valid 오차를 보고 삭제할 행을 고르지 않았다. 제거 규칙은 **train의 elapsed_ms가 train에서 계산한 [Q1−1.5×IQR, Q3+1.5×IQR] 밖에 있으면 제외**하는 것으로 고정했다. 제거 전후에 Pipeline을 새로 만들고 train으로만 전처리와 선형회귀를 학습했다. valid의 행과 정답은 그대로 유지했다.

원본 train 60행의 하한은 `−639.625ms`, 상한은 `3191.375ms`다. 제거 대상이 0건이므로 원본 비교에서는 두 결과가 같다.

| 원본 데이터 실험 | 학습 행 수 | valid MAE(ms) | valid RMSE(ms) |
|---|---:|---:|---:|
| 제거 전 | 60 | 551.797 | 639.996 |
| IQR 규칙 적용 후 | 60 | 551.797 | 639.996 |

### 별도 실험: train 한 행에 오류 주입

차이를 관찰하기 위해 train 순서의 첫 행 `R009`의 정답만 `2349 → 12349ms`로 바꾼 복사본을 만들었다. 주입 위치와 증가량 `10000ms`를 고정하고, 원본 train에서 정한 위 경계를 그대로 적용해 R009를 제외했다. 원본 CSV와 valid는 수정하지 않았다.

| 오류 주입 실험 | 학습 행 수 | valid MAE(ms) | valid RMSE(ms) |
|---|---:|---:|---:|
| R009 오류 주입, 제거 전 | 60 | 538.833 | 658.293 |
| 고정 경계로 R009 제거 후 | 59 | 571.694 | 660.984 |

이 사례에서는 제거 후 두 지표가 모두 나빠졌다. 제거는 R009의 원래 정보를 복원하는 작업이 아니라 한 행을 잃는 작업이며, 이상치 제거가 항상 성능을 개선하지는 않는다. 원래 R009가 오류라는 뜻도 아니다. 실제 업무에서는 큰 값이라는 이유만으로 삭제하지 않고 측정 오류 여부와 업무상 발생 가능한 값인지 조사해야 한다.

재현 순서: train의 `quantile([0.25,0.75])`로 경계를 계산 → train 복사본에 오류 주입 → `between(lower,upper)`로 필터링 → 각 후보의 `build_model(LinearRegression())`을 새로 학습 → 동일한 valid로 MAE·RMSE 계산.

## 막혔을 때 확인

`NoneType` 또는 학습 전 오류가 나오면 먼저 해당 파일의 TODO가 남아 있는지 확인합니다. `NotFittedError`는 fit 부분이 아직 `pass`인지 봅니다. 모델 설정 TODO는 파일이 실행되더라도 잘못된 결과를 낼 수 있습니다.

`ModuleNotFoundError`가 나면 VS Code가 전날의 가상환경을 선택했는지 확인합니다. `root_mean_squared_error`를 찾지 못하면 설치된 scikit-learn 버전을 확인하고 역할 폴더의 `requirements.txt`를 사용합니다.

`파일을 찾을 수 없음`이면 ZIP을 완전히 해제했는지, 코드와 함께 배포된 데이터가 이동·삭제되지 않았는지 확인합니다. 출력 CSV를 Excel에서 열어 둔 경우 저장이 막힐 수 있으므로 닫은 뒤 다시 실행합니다.

오류 메시지를 가리는 `try/except`를 추가하는 과제가 아닙니다. TODO와 파일 위치를 확인하고 계속 막히면 실행 명령과 오류 마지막 줄을 강사에게 보여 줍니다.
