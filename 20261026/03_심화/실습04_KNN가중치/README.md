## 추가 실험 · 거리 정의와 이웃 선택의 경계

> 실험 환경: Python 3.13, scikit-learn 1.8.0, pandas 3.1.0, NumPy 2.5.4. 별도 표기가 없는 추가 실험 수치는 이번에 실행해 확인한 값이며 표시 자릿수로 반올림했다. 실험은 별도 메모리 복사본으로 수행했고 원본 CSV와 main.py는 변경하지 않았다.

### p=1과 p=2가 다른 이웃을 고르는 2차원 예제

질의점 `Q=(0,0)`, 학습점 `A=(3,0)`, `B=(2,2)`를 만들고 K=1로 고정했다. 가상 좌표이며 기존 1차원 입력과 별도 실험이다.

| 학습점 | p=1 맨해튼 거리 | p=2 유클리드 거리 |
|---|---:|---:|
| A=(3,0) | 3 | 3.000 |
| B=(2,2) | 4 | 2.828 |

`p=1`에서는 A, `p=2`에서는 B를 선택했다. p=1은 좌표별 차이의 절댓값 합, p=2는 제곱합의 제곱근을 사용하므로 이웃의 순위가 달라질 수 있다.

```python
for p in [1, 2]:
    model = NearestNeighbors(n_neighbors=1, p=p, algorithm="brute")
    model.fit([[3, 0], [2, 2]])
    distance, indices = model.kneighbors([[0, 0]])
```

### K가 학습 행 수보다 큰 경우

학습 입력 `[[0],[2]]`, 정답 `[0,100]`에 `KNeighborsRegressor(n_neighbors=3)`을 학습한 뒤 `[[1]]`을 예측했다. `fit` 후 예측 시점에 다음 ValueError가 발생했다.

```text
Expected n_neighbors <= n_samples_fit, but n_neighbors = 3, n_samples_fit = 2, n_samples = 1
```

따라서 K 후보는 실제 학습 행 수 이하로 제한해야 한다. 필터링이나 교차검증으로 학습 행 수가 줄어드는 경우에도 이 조건을 확인해야 한다.

### 거리 동률과 입력 순서의 영향

질의 `1`에 대해 입력 `0`과 `2`는 모두 거리 1이다. K=1, `algorithm="brute"`로 정하고 입력과 정답의 쌍을 유지한 채 행 순서만 뒤집었다.

| 학습 입력 순서 | 정답 순서 | 질의 1의 예측 |
|---|---|---:|
| [0,2] | [0,100] | 0 |
| [2,0] | [100,0] | 100 |

이번 환경에서는 동률인 두 이웃 중 선택되는 행이 순서에 따라 달랐다. 이를 모든 알고리즘·버전의 동률 규칙으로 일반화할 수는 없다. K 경계에서 정답이 다른 이웃의 거리가 같으면 결과가 순서에 민감할 수 있으므로 입력 순서와 알고리즘·버전을 함께 기록한다. K=2에서는 두 점을 모두 사용해 두 순서의 균등 평균이 모두 50이 된다. 거리가 같으면 거리 가중치도 같으므로 `weights="distance"`만으로 동률 문제를 해결하지는 못한다.

## 막혔을 때 확인

`NoneType` 또는 학습 전 오류가 나오면 먼저 해당 파일의 TODO가 남아 있는지 확인합니다. `NotFittedError`는 fit 부분이 아직 `pass`인지 봅니다. 모델 설정 TODO는 파일이 실행되더라도 잘못된 결과를 낼 수 있습니다.

`ModuleNotFoundError`가 나면 VS Code가 전날의 가상환경을 선택했는지 확인합니다. `root_mean_squared_error`를 찾지 못하면 설치된 scikit-learn 버전을 확인하고 역할 폴더의 `requirements.txt`를 사용합니다.

`파일을 찾을 수 없음`이면 ZIP을 완전히 해제했는지, 코드와 함께 배포된 데이터가 이동·삭제되지 않았는지 확인합니다. 출력 CSV를 Excel에서 열어 둔 경우 저장이 막힐 수 있으므로 닫은 뒤 다시 실행합니다.

오류 메시지를 가리는 `try/except`를 추가하는 과제가 아닙니다. TODO와 파일 위치를 확인하고 계속 막히면 실행 명령과 오류 마지막 줄을 강사에게 보여 줍니다.
