## 추가 실험 · 특성별 거리 기여와 전체 배열 표준화

> 실험 환경: Python 3.13, scikit-learn 1.8.0, pandas 3.1.0, NumPy 2.5.4. 별도 표기가 없는 추가 실험 수치는 이번에 실행해 확인한 값이며 표시 자릿수로 반올림했다. 실험은 별도 메모리 복사본으로 수행했고 원본 CSV와 main.py는 변경하지 않았다.

### 수치·범주 특성의 거리 기여 분리

기본 전처리는 수치형 두 열을 중앙값 대체 후 표준화하고, 범주형 두 열은 최빈값 대체 후 원핫 인코딩한다. p=2일 때 전체 **거리의 제곱**을 수치형 부분의 제곱차 합과 범주형 부분의 제곱차 합으로 나눌 수 있다. 거리 자체의 합으로 해석하지 않는다.

valid 첫 요청 `R094`와 기본 전처리에서 가까운 train 이웃 5개의 기여를 계산했다. 전처리는 train에서만 학습했다.

| train 이웃 ID | 수치형 제곱차 합 | 범주형 제곱차 합 | 전체 거리 제곱 |
|---|---:|---:|---:|
| R082 | 0.649467 | 0.000000 | 0.649467 |
| R056 | 0.759737 | 0.000000 | 0.759737 |
| R048 | 1.784889 | 0.000000 | 1.784889 |
| R063 | 2.034784 | 0.000000 | 2.034784 |
| R077 | 0.079618 | 2.000000 | 2.079618 |

R077은 수치형 기준으로 매우 가깝지만 범주 차이가 추가되어 다섯 번째 이웃이 됐다. 한 범주형 열의 값이 다르면 원핫 배열의 두 위치가 달라져 제곱차 합에 2가 더해진다. 단, 이는 이 실험처럼 알려진 범주를 일반 원핫 인코딩한 경우의 설명이다.

재현은 `a=pre.transform(X_train)`, `b=pre.transform(X_valid)`로 변환한 후, 첫 valid 행에 대해 `((a[:,:2]-b[0,:2])**2).sum(axis=1)`과 `((a[:,2:]-b[0,2:])**2).sum(axis=1)`을 각각 구한다.

### 별도 실험: 원핫 인코딩을 포함한 전체 배열 표준화

K=5, weights=uniform, p=2와 데이터 분할을 고정하고 다음 세 후보만 비교했다. 주 지표는 valid F1이며 train F1은 진단용이다.

- `none`: 수치형 결측 대체와 범주형 원핫 인코딩만 적용한다.
- `standard`: 수치형에만 StandardScaler를 적용하는 기본 방식이다.
- `all_standard`: `build_model(..., scale="none")`의 전처리 뒤에 별도의 StandardScaler를 넣어 **수치형과 원핫 열 전체**를 표준화한다. 기본 방식과 구분하는 별도 실험이다.

| 전처리 후보 | train F1 | valid F1 |
|---|---:|---:|
| none | 0.709677 | 0.400000 |
| standard: 수치형만 표준화 | 0.461538 | 0.200000 |
| all_standard: 전체 배열 표준화 | 0.482759 | 0.444444 |

전체 배열 표준화는 다음처럼 구성했다. 원핫 결과가 dense 배열인 제공 전처리를 사용하며, 추가 scaler도 train에서만 학습한다.

```python
original = build_model(KNeighborsClassifier(n_neighbors=5), scale="none")
model = Pipeline([
    ("pre", original["pre"]),
    ("all_scale", StandardScaler()),
    ("model", original["model"]),
])
model.fit(X_train, train["failed"])
```

원핫 열까지 표준화하면 등장 빈도가 낮아 분산이 작은 범주의 불일치가 더 크게 반영될 수 있다. 이는 특성별 거리의 가중을 바꾸는 선택이다. 현재 valid에서는 전체 배열 표준화의 F1이 가장 높지만, 작은 valid 한 번의 비교로 일반적인 우월성을 주장할 수 없다. 기존 실습의 minmax 결과와 이 별도 실험을 혼합해 후보를 계속 늘리지 않는다.

## 막혔을 때 확인

`NoneType` 또는 학습 전 오류가 나오면 먼저 해당 파일의 TODO가 남아 있는지 확인합니다. `NotFittedError`는 fit 부분이 아직 `pass`인지 봅니다. 모델 설정 TODO는 파일이 실행되더라도 잘못된 결과를 낼 수 있습니다.

`ModuleNotFoundError`가 나면 VS Code가 전날의 가상환경을 선택했는지 확인합니다. `root_mean_squared_error`를 찾지 못하면 설치된 scikit-learn 버전을 확인하고 역할 폴더의 `requirements.txt`를 사용합니다.

`파일을 찾을 수 없음`이면 ZIP을 완전히 해제했는지, 코드와 함께 배포된 데이터가 이동·삭제되지 않았는지 확인합니다. 출력 CSV를 Excel에서 열어 둔 경우 저장이 막힐 수 있으므로 닫은 뒤 다시 실행합니다.

오류 메시지를 가리는 `try/except`를 추가하는 과제가 아닙니다. TODO와 파일 위치를 확인하고 계속 막히면 실행 명령과 오류 마지막 줄을 강사에게 보여 줍니다.
