# 실습 07 · 함께 확인한 결과

실제 localhost:8000 서버 검증과 임시 파일 자동 테스트 결과를 구분해 기록했습니다.
실제 ID: A=4(유지), B=5(수정), C=6(삭제). 서로 다른 항목에 유지·수정·삭제 역할을 나눴습니다.

| 동작 | 예상 | 실제 | 파일 확인 |
|---|---|---|---|
| 정상 등록 | 201, 새 id | 실제 서버에서 A·B·C 모두 201, ID 4·5·6 | entries 3→6건, next_id 4→7 |
| 같은 id 상세 조회 | 200, 등록 내용 | 등록 직후 각각 GET 200, POST 응답과 전체 내용 일치 | 저장된 각 항목과 응답 일치 |
| 같은 id 본문 수정 | 200, 같은 id | B PUT 200·GET 200, ID 5 유지 | B 본문 변경, entries 6건·next_id 7 유지. 첫 재시작 후에도 유지 |
| 없는 id 수정 (정상 Body) | 404 | 자동 테스트에서 ID 9999 PUT 404. 실제 서버 추가 요청은 미실시 | 자동 테스트의 임시 파일 바이트 불변 |
| content 빈 문자열 등록 | 422, 파일 불변 | 실제 서버에서 422 | 실제 파일 바이트 불변, entries 6건·next_id 7 유지 |
| 같은 id 삭제 | 204, 빈 본문 | C DELETE 204, 응답 본문 빈 바이트 | ID 6 제거, entries 5건·next_id 7 유지 |
| 삭제한 id 조회 | 404 | C GET 404, 두 번째 재시작 후에도 404 | ID 6 부재 유지. A·B 및 기존 ID 1·2·3 보존 |

응답의 성공과 파일 저장 성공을 어떻게 함께 확인했는가: 각 HTTP 요청의 상태 코드·본문을 확인하고 실제 JSON 파일을 직접 읽어 항목 내용·entries 수·next_id를 비교했습니다. B 수정 후와 C 삭제 후에는 실제 프로세스를 SIGINT로 종료하고 새 프로세스를 실행해 상태가 유지되는지 재조회했습니다. 자동 테스트 21개 통과도 별도로 확인했습니다.

이 API는 지식을 관리하는가, 질문의 답변을 생성하는가: 지식을 등록·조회·수정·삭제하는 API입니다. LLM 호출이나 질문 답변 생성 기능은 없습니다.

최종 실제 파일: 5건(ID 1·2·3·4·5), next_id=7. 검증 후 사용자 요청으로 서버를 정상 종료했습니다.
