## 1. 사용자와 목적

대상 사용자: Python·FastAPI 실습을 진행하며 학습 안내와 질문 방법을 정리하려는 수강생입니다.
서비스 목적: 파일 보관 방법, 질문 방법, 공지 등의 지식을 제목·본문·분류로 등록하고 목록·상세 조회, 수정, 삭제하여 관리합니다.
오늘 구현한 범위 / 아직 구현하지 않은 범위: JSON 파일 기반 지식 CRUD, category 필터, 입력 검증, HTTP 응답과 저장 결과를 확인하는 자동 테스트를 구현했습니다. 인증·권한, DB 연동, 의미 검색, LLM 답변 생성은 구현하지 않았습니다.

## 4. 요청 → 예상 → 실제 → 파일 변화

| 요청·동작                           | 예상                      | 실제 결과                                                                      | 확인한 파일 변화                                                        |
| ----------------------------------- | ------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| POST A·B·C 및 목록·상세 조회        | 201·200, N+3개            | POST 모두 201, ID 4·5·6 발급. 목록 및 각 상세 GET 200, 응답 내용 일치          | entries 3→6건, next_id 4→7, A·B·C 저장                                  |
| B PUT (세 필드 모두 전송)           | 200, ID·개수·next_id 유지 | PUT 200, GET 200. 전체 본문과 기존 ID 5 일치                                   | B content가 `오류 메시지와 함께 질문합니다.`로 변경. 6건·next_id=7 유지 |
| 첫 번째 Ctrl+C·재실행 후 B 조회     | 수정 본문 유지            | SIGINT 정상 종료 후 새 프로세스 실행. B GET 200, 수정한 전체 내용과 ID 일치    | 종료·재실행 전후 파일 바이트 일치. 수정한 B, 6건·next_id=7 유지         |
| content="" POST                     | 422, 목록과 next_id 불변  | 422, 요청 전후 파일 바이트 전체 일치                                           | entries 6건·next_id=7 유지                                              |
| C DELETE 및 상세 조회               | 204·빈 본문, GET 404      | DELETE 204·빈 본문, ID 6 GET 404                                               | ID 6 제거, entries 6→5건, next_id=7 유지                                |
| 두 번째 Ctrl+C·재실행 후 A·B·C 조회 | A/B 200, C 404, 최종 N+2  | SIGINT 정상 종료 후 새 프로세스 실행. A/B GET 200, C GET 404. 목록 GET 200·5건 | 종료·재실행 전후 파일 바이트 일치. 5건·next_id=7 유지                   |
| A와 프로젝트 전 기존 지식 조회      | 원래 내용 그대로          | 두 번째 재시작 후 A와 기존 ID 1·2·3의 GET 응답이 원본과 일치                   | 최종 파일에 기존 3건과 A 원본 유지, 수정한 B 포함                       |

422 전후 next_id: 7 → 7.
최종 목록 수와 기대한 N+2: 5건 = 시작 3건 + 2건.
재시작 사이 seed 복사·reset·파일 수동 편집을 하지 않았는가: 하지 않았습니다. 같은 실제 JSON 파일을 두 차례 재시작 내내 사용했고 API 요청으로만 데이터를 변경했습니다.

## 5. 설명과 한계

내가 고른 요청의 흐름: `POST /api/knowledge`가 오면 FastAPI가 `app/schemas.py`의 `KnowledgeWrite`로 title·content·category의 필수 여부와 길이를 검증합니다. 검증에 성공하면 `app/routers/knowledge.py`의 `create_knowledge()`가 `payload.model_dump()`를 `repo.create()`에 전달합니다. `app/repositories/json_knowledge.py`는 LOCK 안에서 파일을 읽고 입력 복사본에 ID를 지정한 뒤 entries에 추가하고 next_id를 증가시켜 저장합니다. Router가 반환한 항목은 `Knowledge` 응답 모델을 거쳐 201 JSON 응답이 됩니다. 입력 검증에 실패하면 422가 반환되며 생성 함수가 호출되지 않아 파일은 바뀌지 않습니다.

형식 검증과 지식 내용의 사실성 확인이 다른 이유: 현재 검증은 필수 필드, 자료형, 문자열 길이 같은 입력 형식을 검사합니다. 예를 들어 길이 조건을 충족하는 잘못된 안내도 저장될 수 있으며, 본문의 사실 여부나 정보의 최신성은 확인하지 않습니다.

RAG·Agent 플랫폼에서 이 API의 역할: 검색이나 답변 생성에 사용할 원본 지식을 등록·조회·수정·삭제하는 관리 API 역할입니다. 향후 검색 도구나 지식 공급원으로 연결할 수 있지만, 현재는 임베딩·벡터 검색·LLM 호출·Agent 실행을 구현하지 않았습니다.

현재의 한계 (로컬·인증/권한·검색/생성): 로컬의 단일 JSON 파일을 사용하고 인증·사용자별 권한이 없습니다. LOCK은 단일 프로세스 내부에서만 유효하여 여러 서버 프로세스가 같은 파일을 동시에 수정하는 상황을 보호하지 않습니다. 검색은 category 문자열의 정확한 일치만 지원하며 의미 검색과 답변 생성은 제공하지 않습니다.

응용 선택: 자동 테스트에서 `category=api`는 초기 ID 2·3을 반환하고, `category=unknown`은 200과 빈 배열을 반환하는 것을 확인했습니다. 최종 실제 파일 기준 분류는 setup: ID 1, api: ID 2·3, learning: ID 4, help: ID 5입니다. 이는 파일 내용 기준이며 최종 서버에 필터 요청을 별도로 보낸 결과와 구분합니다.

심화 선택: 아래 명령으로 자동 테스트를 실행해 21개 통과, TestClient의 httpx 사용 중단 예정 경고 1건을 확인했습니다.

자동 테스트는 fixture가 각 테스트마다 만든 임시 파일과 TestClient를 사용하므로 실제 서버 프로세스 재시작까지 검증하지 않습니다. 이를 보완해 실제 `localhost:8000` 서버와 저장 파일로 두 차례 SIGINT 종료·재실행을 수행했고, 수정·삭제 결과가 유지됨을 확인했습니다. 검증 후 사용자 요청으로 마지막 서버도 정상 종료했으며 8000번 포트가 닫힌 것을 확인했습니다.

## 파일 출력 확인 기록 — 실제 서버 검증

검증 시작 시 실제 파일은 3건·next_id=4였습니다. 실제 서버 요청 및 두 차례 재시작을 마친 뒤 읽은 `data/knowledge.json`은 다음과 같습니다.

```json
{
  "next_id": 7,
  "entries": [
    {
      "id": 1,
      "title": "가상환경",
      "category": "setup",
      "content": "프로젝트별 패키지를 분리한다."
    },
    {
      "id": 2,
      "title": "서버 실행",
      "category": "api",
      "content": "uvicorn으로 개발 서버를 켠다."
    },
    {
      "id": 3,
      "title": "입력 오류",
      "category": "api",
      "content": "422이면 입력값을 확인한다."
    },
    {
      "title": "파일 보관",
      "content": "개인 폴더에 보관합니다.",
      "category": "learning",
      "id": 4
    },
    {
      "title": "질문 방법",
```

C의 ID 6은 삭제됐으며 다음 발급 ID는 7입니다. 파일 초기화나 되돌리기를 하지 않고 이 최종 상태를 유지했습니다.
